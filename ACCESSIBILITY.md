# Accessibility Statement & Standards

At **Clipit**, we believe that digital video and creation tools should be accessible to everyone, including people with visual, auditory, cognitive, and motor impairments.

We are committed to ensuring that both the **Clipit Web Studio application** and the **short-form videos generated by Clipit** adhere to the **Web Content Accessibility Guidelines (WCAG) 2.1 Level AA** standards.

---

## 1. Web Studio Application Accessibility

The Clipit Web Studio (FastAPI + React 19) is engineered with the following accessibility features:

### Keyboard Navigation & Focus Management
- **Full Keyboard Operability**: Every interactive element—buttons, tabs, form inputs, modals, video playback controls, and job management actions—is fully operable using only a keyboard (`Tab`, `Shift+Tab`, `Enter`, `Space`, `Escape`, and arrow keys).
- **Visible Focus Rings**: We provide high-visibility `:focus-visible` outlines across all controls so keyboard users always know their current focus position.
- **Modal Focus Trapping**: Dialog overlays trap keyboard focus within the dialog and automatically close on `Escape`.
- **Skip Links & Landmarks**: Semantic HTML5 landmark regions (`<header>`, `<nav>`, `<main>`, `<aside>`) enable rapid navigation with screen reader shortcut keys.

### Visual Ergonomics & Color Contrast
- **WCAG 2.1 AA Contrast**: All body text, buttons, and status badges meet or exceed the minimum contrast ratio of **4.5:1** against their background colors (and **3:1** for large text and UI components).
- **Dual Light & Dark Themes**: Both themes are tuned with accessible color palettes to minimize eye strain and assist users with light sensitivity or low vision.
- **Not Color-Reliant**: Statuses (Completed, Processing, Queued, Error) convey information through icons and text labels, never color alone.

### Screen Reader Support & Semantics
- **ARIA Live Regions**: Real-time pipeline progress meters use `aria-live="polite"` and standard `role="progressbar"` attributes (`aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax="100"`) so screen readers announce job stage transitions without overwhelming the user.
- **Explicit Labels**: All form fields on the **New Job**, **Presets**, and **Settings** pages have explicit associated `<label>` tags and descriptive helper text.
- **Decorative Elements**: Non-informational icons and graphics carry `aria-hidden="true"`.

### Reduced Motion
- The interface respects operating system preferences via the CSS media query:
  ```css
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration: 0.01ms !important;
      transition-duration: 0.01ms !important;
    }
  }
  ```
  Users with vestibular disorders or motion sensitivity experience instant state transitions without spinning or pulsing animations.

## 2. Accessible Video Output Standards

Short-form videos produced by Clipit are designed to maximize comprehension and accessibility for diverse audiences:

### Kinetic Open Captions (Subtitles)
- **High-Legibility Typography**: Subtitle presets (e.g. Hormozi, Clean Modern, Neon) utilize heavy, easily readable typefaces with thick solid outlines (`Outline=3` to `Outline=4`) and drop shadows (`Shadow=2`). This guarantees legibility regardless of video background luminance.
- **Safe Zone Positioning**: Subtitles are positioned strictly within platform safe zones (`MarginV=140` on 1080x1920 portrait formats) to ensure captions are never obscured by TikTok, Instagram Reels, or YouTube Shorts interface buttons.
- **Sidecar Subtitle Files**: Along with burned-in captions, Clipit exports clean `.srt`, `.vtt`, and `.ass` sidecar files in the output directory, enabling viewers to use custom fonts, sizes, or third-party assistive readers.

### Audio Normalization & Vocal Clarity
- **Automated Loudness Normalization**: Through the `--normalize-audio` flag (powered by FFmpeg `loudnorm`), audio is mastered to the broadcast **EBU R128 / -14 LUFS** standard with true-peak limiting (`-1.5 dBFS`).
- **Dynamic BGM Ducking**: Background music is automatically ducked under spoken dialogue by 14–18 dB to ensure speech frequencies remain crystal clear for individuals with hearing impairments or auditory processing disorders.

## 3. Auditing & Testing Methodology

We continually test Clipit using automated and manual accessibility testing workflows:

1. **Automated Audits**:
   - Google Chrome DevTools Lighthouse Accessibility audit (scoring ≥ 95%).
   - `axe-core` accessibility engine integration during UI testing.
2. **Keyboard-Only Walks**: Periodic end-to-end manual walks creating jobs, inspecting clips, and configuring settings using solely keyboard inputs.
3. **Screen Reader Validation**: Verification with NVDA and Orca on Linux, and VoiceOver on macOS.
